ricochet uses OpenID Connect (OIDC) for login, so you can connect any OIDC-compliant identity provider.

## Requirements

The OIDC provider must support:

- **Claims**: `email` and `profile`
- **Grant Type**: Authorization Code Flow
- **PKCE**: code challenge with the `S256` method

ricochet uses the subject identifier (`sub`) as the unique user ID.
It collects the `email` claim for future SMTP features.

Every sign-in sends a PKCE challenge, then sends the matching verifier in the token exchange.
Your client registration must allow PKCE.
If your provider has a PKCE setting, set it to `S256`.
You cannot turn PKCE off.

Since PKCE protects the flow, `client_secret` is optional and ricochet can run as a public client.
The one exception is Microsoft Entra group and avatar sync, which needs the secret to call Microsoft Graph.

## Configuration

Add this to your `ricochet-config.toml`:

```toml
[auth.oidc]
issuer_url = "https://auth.example.com/"
client_id = "your_client_id"
client_secret = "your_client_secret"
redirect_url = "https://your-ricochet-domain.com/oauth/callback"
display_name_claim = "preferred_username"  # Optional, defaults to "preferred_username"
groups_claim = "groups"  # Optional, defaults to "groups"
```

<Aside type="caution">
  The redirect URL **must** use the `/oauth/callback` path so it works with the ricochet CLI.
</Aside>

#### Configuration Fields

| Field                | Required | Description                                                                                                                                                                                                                 |
| -------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `issuer_url`         | Yes      | Your OIDC provider's issuer URL. Must start with `https://`                                                                                                                                                                 |
| `client_id`          | Yes      | OAuth client ID from your OIDC provider                                                                                                                                                                                     |
| `client_secret`      | No       | OAuth client secret from your OIDC provider. Leave it out to register ricochet as a public client. Microsoft Entra group and avatar sync needs it.                                                                          |
| `redirect_url`       | Yes      | Callback URL users return to after login. **Must be** `https://your-domain/oauth/callback`                                                                                                                                  |
| `display_name_claim` | No       | OIDC claim to use for the display name. Defaults to `preferred_username`                                                                                                                                                    |
| `groups_claim`       | No       | Name of the OIDC claim that holds the user's groups. The value may be an array of strings, a single string, or a comma-separated string. Leave it out to turn off group sync at login.                                      |
| `provider`           | No       | Identity provider type. Set to `"entra"` for Microsoft Entra ID. For all other providers, leave it out or set it to `"oidc"`. With `"entra"`, `groups_claim` defaults to `"groups"` and background directory sync turns on. |
| `sync_interval`      | No       | How often, in minutes, to run background group sync from the IdP directory. Works only with `provider = "entra"`. Leave it out to sync groups at login only.                                                                |

## SSO Groups

When `groups_claim` is set (default `"groups"`), ricochet reads the user's groups from that claim in each ID token at login.
It stores a local copy of those groups.
You can then grant a role on a content item to a group name in the collaborators dialog.
Any user whose ID token held that group at their last login gets the role.

Keep these points in mind:

- **Groups refresh on every login.** If you add a user to a group in your IdP after their last ricochet login, they get the role only after they sign in again.
- **Names must match exactly, including case.** The group name you type in the collaborators dialog must match the string in the ID token byte for byte.

## Microsoft Entra ID (Azure AD)

### Issuer URL

With Microsoft Entra ID, you must use the v2.0 issuer URL.
The v1 issuer (`https://sts.windows.net/{tenant-id}/`) returns a non-standard discovery document that ricochet's OIDC client cannot read.

```toml
[auth.oidc]
provider = "entra"
issuer_url = "https://login.microsoftonline.com/{tenant-id}/v2.0"
client_id = "your_client_id"
client_secret = "your_client_secret"
redirect_url = "https://your-ricochet-domain.com/oauth/callback"
```

Replace `{tenant-id}` with your Azure tenant ID.

<Aside type="note">
  Background directory sync needs the **`Group.Read.All`** Microsoft Graph application permission on the app registration, granted by an administrator.
  Without it, ricochet still syncs groups at login from the ID token, but it cannot pull display names from the Graph API.
</Aside>

### Groups claim

Entra does not send a `groups` claim by default.
Turn it on in the app registration under *Token configuration → Add groups claim*.

<Aside type="note">
  Entra applies a "group overage" limit at about 200 groups per user.
  Past that point, Entra stops putting the groups array in the token and points to Microsoft Graph instead, which ricochet does not follow yet.
  Users with that many groups appear to have no groups until ricochet supports this.
</Aside>

Pick *Group ID* (the default) or *sAMAccountName*, based on what your tenant supports.

<Aside type="caution">
  Entra sends **group object IDs (GUIDs)** for cloud-only groups, even when you pick the `sAMAccountName` format.
  Entra fills `sAMAccountName` only for groups synced from on-premises Active Directory through Entra Connect.
  If you created your groups in Entra, the `groups` claim holds a GUID such as `a3f2c1e8-...`.
  With `provider = "entra"` set, ricochet turns these GUIDs into display names through Microsoft Graph.
</Aside>

### User avatars

Standard OIDC providers fill user avatars from the `picture` claim.
Entra leaves out that claim and serves photos only from Microsoft Graph.
With `provider = "entra"` set, ricochet fetches each user's photo at login from `GET /users/{id}/photo/$value`.
It resizes the photo to a 128×128 PNG and stores it, but never overwrites an avatar the user uploaded.

<Aside type="note">
  Fetching avatars needs the **`User.Read.All`** Microsoft Graph application permission on the app registration, granted by an administrator (admin consent).
  The group permissions above do not cover `/users/{id}/photo`.
  ricochet fetches avatars on a best-effort basis.
  A missing permission, photo, or `oid` claim never blocks login.
</Aside>

## Requiring Authentication

By default, users who are not signed in can browse the "Explore" page and view public content.
To require login for all access, turn on the `require_authentication` option:

```toml
[auth]
require_authentication = true
```

Or set the environment variable:

```bash
RICOCHET_AUTH__REQUIRE_AUTHENTICATION=true
```

### Behavior

| Setting                        | Unauthenticated User Access                          |
| ------------------------------ | ---------------------------------------------------- |
| `require_authentication=false` | Can view Explore page and public content only        |
| `require_authentication=true`  | Redirected to sign-in page on all routes             |

With `require_authentication` on, users see a full-screen login page with SSO sign-in.
With it off (the default), users who are not signed in can browse public content.
They see a sign-in prompt in the sidebar for protected features such as deployment, API keys, and settings.
